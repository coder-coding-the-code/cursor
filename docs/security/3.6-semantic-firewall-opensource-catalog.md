# 3.6 语义防火墙：开源检测项目清单

> 对应组件：**Semantic Pipeline Vulnerability Filter（语义管道漏洞过滤器）**  
> 定位：ECS 语义管道上的强制语义防火墙。每一条语义消息都必须过墙。  
> 本文整理大模型领域可复用的**开源检测 / 护栏 / 红队**项目，按 3.6 要求的八类威胁归类，并给出官方仓库与模型地址。

配套方案见同目录的落地设计（若已合入）：[3.6-semantic-pipeline-vulnerability-filter.md](./3.6-semantic-pipeline-vulnerability-filter.md)。

---

## 0. 怎么用这份清单

没有单一开源项目能覆盖全部八类威胁。成熟做法是**分层组合**：

| 层 | 职责 | 放不放进热路径 |
| --- | --- | --- |
| L0 规范化 | Unicode / 隐藏通道 / 解码 | 每条消息，不可跳过 |
| L1 规则扫描 | 已知注入、越狱话术、编码 | 每条消息 |
| L2 分类器 | 改写后的注入 / 越狱 | 每条消息（可降级小模型） |
| L3 结构与本体 | Schema、SHACL、图谱异常 | RDF / 补丁 / 结构化载荷 |
| L4 意图对齐 | Agent 轨迹是否偏离用户目标 | tool_call / 多步 trace |
| L5 工具门 | 调用前授权、MCP 清单扫描 | 工具执行点，fail-closed |
| 红队 | 测过滤器是否失效 | **不进**线上拦截 |

原则：

1. **分类器 ≠ 防火墙**。Prompt Guard / DeBERTa 只给文本打标；工具滥用和提权必须在执行点用策略引擎。
2. **隐藏指令必须在语义模型之前做**。否则模型可能已经「看见」注入。
3. **红队工具不要塞进线上拦截**。garak / PyRIT / FuzzyAI 用来证明过滤器失效。
4. **本体投毒最空**：工业级成品几乎没有，要借 RAG / 图谱异常检测算法自研闸门。

## 1. 推荐最小组合（ECS 热路径）

若只先接四件套，优先：

1. [LlamaFirewall](https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall) + [Prompt Guard 2](https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-86M)  
2. Unicode / 隐藏指令扫描（LlamaFirewall `HiddenASCIIScanner`，或 [ragaudit](https://github.com/kriskimmerle/ragaudit) / [ipi-check](https://github.com/v0lka/ipi-check)）  
3. [Open Policy Agent](https://github.com/open-policy-agent/opa)（每次 tool call 前裁决）  
4. [mcp-scan / Snyk Agent Scan](https://github.com/snyk/mcp-scan)（工具清单变更，冷路径）

冷路径再补：[ragaudit](https://github.com/kriskimmerle/ragaudit)、[RAGDefender](https://github.com/SecAI-Lab/RAGDefender)、SHACL/OWL。  
异步路径再补：AlignmentCheck、LLM-judge。  
持续验证：[garak](https://github.com/NVIDIA/garak) + [PyRIT](https://github.com/microsoft/PyRIT) + [promptfoo](https://github.com/promptfoo/promptfoo)。

建议流水线：

```text
语义消息
  │
  ├─ L0  规范化     Unicode NFKC、去零宽/Bidi、解码 Base64/HTML 隐藏层
  │                 HiddenASCIIScanner / ragaudit / ipi-check
  │
  ├─ L1  注入/越狱   Prompt Guard 2 + ProtectAI DeBERTa（双模型投票）
  │
  ├─ L2  结构/本体   Schema + SHACL/OWL + RAGDefender/RAGSieve
  │                 Granite Guardian groundedness
  │
  ├─ L3  意图对齐    LlamaFirewall AlignmentCheck（对 agent trace）
  │
  ├─ L4  工具门      mcp-scan（清单）+ OPA/Cedar（每次调用）
  │                 CodeShield（代码类工具）
  │
  └─ L5  持续验证    garak + PyRIT + promptfoo（测过滤器，不进热路径）
```

### 2.2 Ontology Poisoning（本体 / 知识投毒）

没有像 Prompt Guard 那样的现成「本体投毒检测器」。开源基本落在 **RAG 语料投毒 / 知识图谱约束** 上。

| 项目 | 切入点 | 说明 | 开源地址 |
| --- | --- | --- | --- |
| ragaudit | 入库前静态扫描 | 嵌入前扫文档：隐藏指令、注入模式、角色劫持、Base64、假权威引用。对标 OWASP ASI06 | https://github.com/kriskimmerle/ragaudit |
| RAGDefender | 检索后过滤 | 不重训、少调 LLM，滤 PoisonedRAG / GARAG 类投毒段落 | https://github.com/SecAI-Lab/RAGDefender |
| RAGuard | 零知识投毒识别 | leave-one-out 影响分数找「最像被投毒」的检索段落 | https://github.com/RAGuard-AI/RAGuard |
| RAGSieve | 在线 + 离线 | RSQ：当前 query 的 top-k vs 邻域对比；RSG：全库语义图异常密度 | https://github.com/XrazyMee/RAGSieve |
| Granite Guardian 仓库 | RAG 接地 / 幻觉 | 预置 groundedness、relevance、function-call hallucination，可 BYOC | https://github.com/ibm-granite/granite-guardian |
| Granite Guardian 4.1 8B | 开源权重 | 同上的模型权重 | https://huggingface.co/ibm-granite/granite-guardian-4.1-8b |
| pySHACL | 本体约束 | OWL/RDF 形状校验，结构合法性 | https://github.com/RDFLib/pySHACL |
| Apache Jena | OWL/RDF 栈 | Java 侧推理与 SHACL | https://github.com/apache/jena |
| RDFLib | RDF 工具库 | Python 图操作，常与 pySHACL 联用 | https://github.com/RDFLib/rdflib |

对真正的 **OWL/RDF 本体投毒**，工程上通常要自建：

- SHACL / OWL 一致性校验（结构合法性）
- 图谱邻域异常（度、关系类型突变、矛盾公理）
- 把 RAGSieve 的「局部语义对比」迁到三元组 / 公理嵌入上

### 2.3 恶意语义结构（Malicious Semantic Structure）

指「看起来像合法语义图 / 消息，实则改写意图、权限或工具流」的结构。没有专用「恶意 AST 扫描器」，靠 schema + 本体一致性 + 目标对齐三件套。

| Invariant Guardrails | 分析工具描述与调用流，抓 toxic flow、tool shadowing | https://github.com/invariantlabs-ai/invariant |
| Invariant Gateway | LLM / MCP 代理，在请求前后执行规则 | https://github.com/invariantlabs-ai/invariant-gateway |

| Guardrails AI / OpenAI Guardrails | JSON Schema、工具参数、输出结构校验 | 见 §2.1 |
| Granite Guardian BYOC | 用自然语言定义「是否构成越权结构」 | https://github.com/ibm-granite/granite-guardian |

### 2.5 隐藏指令（Hidden Instructions）

隐藏指令必须走 **字节 / Unicode 层**，不能只靠语义分类器——分类器经常把看不见的字符当噪声丢掉。

| 项目 | 检测手段 | 开源地址 |
| --- | --- | --- |
| LlamaFirewall HiddenASCIIScanner | Unicode Tag 块、零宽字符、Bidi override、全角、跨脚本同形字 | https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall （`scanners/hidden_ascii_scanner`） |
| ragaudit | 零宽/Bidi、同形字、HTML `display:none`、Markdown 注释、Base64、URL/Unicode 转义 | https://github.com/kriskimmerle/ragaudit |
| ipi-check | ANSI、Unicode Tag、variation selector、PUA、同形字 + 多语言注入正则；可出 SARIF | https://github.com/v0lka/ipi-check |
| ipi-detect | 内容扫描 + **行为监控**（工具调用序列是否像在执行注入） | https://github.com/pjcampbe11/ipi-detect |

### 2.6 权限提升尝试（Privilege Escalation）

LLM 侧的提权 = 诱导模型调用更高权限工具、改角色、绕过审批。**纯文本分类不够**，要在工具执行前做策略裁决。模型可以「想」调什么工具，能不能执行由策略引擎决定，且 fail-closed。

| 项目 | 角色 | 开源地址 |
| --- | --- | --- |
| Open Policy Agent (OPA) | 每次 tool call 前用 Rego 判 allow / deny / escalate | https://github.com/open-policy-agent/opa |
| Vercel AI SDK `policy-opa` | 把 OPA 接到 `toolApproval`；middleware 可在模型看到工具列表前裁剪能力 | https://github.com/vercel/ai/tree/main/packages/policy-opa |
| AWS Cedar | 默认拒绝的授权语言 | https://github.com/cedar-policy/cedar |
| Cedar Agent 授权示例 | 委托链上的最小权限，对标 OWASP ASI03 | https://github.com/aws-samples/sample-cedar-agentic-ai-authorization |
| Microsoft Agent Governance Toolkit | 把 OPA / Cedar / YAML 接到同一套评估管道 | https://github.com/microsoft/agent-governance-toolkit |
| LlamaFirewall AlignmentCheck | 检测「用户目标 vs 实际动作」偏离（语义层提权） | https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall |
| ClawMoat | 宿主机侧：文件 / Shell / 网络 / 凭据，补模型层看不到的动作 | https://github.com/darfaz/clawmoat |

### 2.7 语义混淆攻击（Semantic Obfuscation）

包括：同义改写、编码（Base64 / ROT / Unicode）、语言切换、payload 拆分、同形字、多轮渐进。分类器对「改写后的注入」召回会掉。线上要：**规则（编码/零宽）+ 嵌入相似度 + 可选 LLM-judge**。

| 能力 | 项目 | 开源地址 |
| --- | --- | --- |
| 编码 / 混淆探针（评测） | garak `encoding`、FuzzyAI、PyRIT converters | 见 §3 |
| 释义后仍像攻击（运行时） | inferwall FAISS + MiniLM；自建已知攻击向量库 | https://github.com/Genmin/inferwall |
| Unicode / 同形字 | HiddenASCIIScanner、ragaudit、ipi-check | 见 §2.5 |
| 多轮渐进越狱 | PyRIT Crescendo；运行时用 AlignmentCheck 看整段 trace | 见 §3 与 §2.3 |

## 7. 选型时注意的坑

1. **分类器 ≠ 防火墙**：Prompt Guard / DeBERTa 只打标文本；工具滥用和提权必须在执行点用策略引擎。
2. **维护状态**：LLM Guard、Rebuff、Vigil 不要当新底座。
3. **本体投毒最空**：ECS 若本体是一等公民，这部分大概率要自研，开源只能借 RAG / 图谱异常检测的算法。
4. **隐藏指令必须在语义模型之前做**：否则模型可能已经「看见」了注入。
5. **红队工具不要塞进线上拦截**：garak / PyRIT / FuzzyAI 用来证明过滤器失效，不是用来当过滤器。

## 8. 参考标准

- [OWASP Top 10 for LLM Applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/)（尤其 LLM01 注入、LLM06 过度代理、LLM07 系统提示泄漏、LLM08 向量/检索投毒）
- [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications/)（目标劫持、工具误用、身份与权限滥用、供应链/MCP、记忆投毒）
- W3C SHACL、OWL 2（本体约束与一致性）
- Unicode Security Considerations（同形字、BIDI、不可见字符）
- MLCommons / Llama Guard 危害分类（内容安全，互补于注入检测）
